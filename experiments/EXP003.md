## Candidate pools and sampling

For each FIT/TUNE/EVALUATION S1, retrieve compact_18 independently from S2/S3,
retain every candidate passing **any existing active pass-rank limit (40)**,
deduplicate and build features. **Do not apply the old total 60/source cap**.
There is no one-match or post-score maximum: all scores >= threshold are matches.
No labels influence retrieval. Positives missing from this pool are never added.

Important ceiling distinction: EXP002f's 0.965247 `recall_before_cap` measures
the raw pool, before pass eligibility. EXP003 measures raw and eligible retained
links separately in `pairs/pool_counts.csv`; it does not assume they are equal.
Final versus eligible loss is matcher FN; missing eligible links are blocking FN.

FIT sampling reuses `TrainingPairSampler` **per entity**: retain every positive,
up to 20 hardest negatives and up to 3 nonduplicate easy negatives. Hardness is
`0.7 * EXP001_rule_score + 0.3 * min(best_retrieval_score, 100)`. Easy candidates
have hardness <=55 and are selected by stable pair hash; hard ties use candidate
ID. Both sources share the per-S1 negative budget. Sampling counts and ratios
are recorded; country/source/partition counts are saved. TUNE/EVALUATION pairs
are never negative-subsampled. Empty-candidate S1 remain in metric denominators.

Rows are appended to float32 binary matrices with TSV pair metadata. FIT stores
only sampled rows; TUNE/EVALUATION store complete eligible pools. Memory maps
and per-S1 reads avoid retaining millions of feature tuples in Python. Separate
compact_14 tune/evaluation artifacts retain frozen pass limits **and total 60**
for the deployable rule fallback. This adds a bounded second retrieval on
14,001 development/evaluation entities, not a new blocker search.

## Bundles / licensing / failure handling

Each trusted-local joblib bundle contains model/threshold, exact feature order,
frozen blocker config/hash and pool semantics, normalization version, source-code
hashes, git commit, seeds, split counts/subset hash, Python/package versions and
MIT model-weight license. Models are trained locally from Amazon data, not
external pretrained models. Runtime scikit-learn remains BSD-3-Clause; project
weights are licensed under `docs/MODEL_LICENSE.txt`. No new ML dependency was
introduced. joblib/threadpoolctl already in the lockfile are declared directly.
The atomic JSON completion sidecar includes a SHA256 checksum verified before
unpickling; keep the `.joblib` and matching `.json` together. Loading enforces
identical feature/config/code/package versions. Use the same
checkout and pinned environment for inference; never load untrusted joblib files.

Rule bundles are tuned/saved **before learned fits**. `rule14.joblib` and alias
`rule.joblib` are available even if a subsequent fit fails. Exceptions are logged;
if both models fail the summary recommends rule. Hard process termination can
leave no final summary but the completed fallback bundle is still usable.
`--rule-only` supports a fallback-only run. No automatic broader data/search.

Pair caches have an atomic completion/identity marker plus SHA256 checksums for
every expected pair/count artifact. A restarted failed training invocation can
reuse completed compatible pairs after verification; corruption is refused.
An interrupted pair-generation
directory is preserved and refused: use a fresh result directory after diagnosis.
Completed training results are never overwritten. This protects evidence;
partial model fitting itself is not checkpointed.

## Resumable inference / exact output contract

`scripts/infer_exp003.py` is separate and reads **no ground truth**. Each of four
workers streams TEST S1; input row position modulo 4 assigns a disjoint stable
shard (S1 fingerprint prevents changed ordering on resume). Each worker opens
its own S2/S3 read-only connections and holds only one entity's pairs/features.
BLAS/OpenMP threads are limited to one per worker. Worker-local SQLite records
candidate and match lists transactionally every 100 processed S1; committed
rows survive interruption. A lock prevents two workers writing one shard.
Restarting rescans the input but skips already committed positions; at most
99 uncommitted queries repeat. Completed shards with valid file checksums are
reused without rescoring or rewriting published files. Incomplete publication is
recoverable from the committed checkpoint. Changed inputs during inference or
merge cause failure instead of publishing mixed-input results.

Bundle/source/index identity is bound to the checkpoint. Mixed models, changed
inputs or mixed smoke/full shards fail closed. Index fingerprints use size/mtime
metadata, not cryptographic full-index/raw hashes. Preserve original source
timestamps when transferring indexes/data to AWS. Never bypass a mismatch.
Completed shard outputs have checksums and completion markers.

Merge streams S1 in original order and reads the corresponding shard's next row.
A disk UNIQUE constraint catches duplicate S1 across shards; missing/extra rows,
wrong ordering, duplicate target IDs and matches outside candidates are errors.
Only a fully validated merge is atomically published as the requested directory.
An interrupted `.building` merge directory is preserved; choose a fresh merge
destination. No entire TEST S1 set or candidate matrix is loaded into RAM.

Official resource contract:

- `matching_results.tsv`: `source1_entity_id<TAB>matched_entity_ids`.
- `candidate_pairs.tsv`: `source1_entity_id<TAB>candidate_entity_ids`.
- Exactly one row per required S1 in each file; UTF-8 TSV; comma-separated,
  sorted unique S2/S3 IDs, no list quoting; empty second field for no matches.
- Candidate lists are **exactly the candidates scored** by the chosen pipeline.
  Learned: compact_18 eligible, no total cap. Rule: compact_14 capped pool.
- Matches are always a subset of candidates. Target existence follows from
  matched TEST-index provenance; synthetic tests also run the official validator
  with `--check-ids` against all three fixture sources.

Smoke mode defaults to the first 100 S1 (max 1,000); its merged output is clearly
marked partial and **must not be submitted**. Full TEST requires explicit
`--allow-full-test` on both inference and merge; it is mutually exclusive with
`--smoke-limit`. No index-build option exists. No automatic upload/submission.

## Exact AWS commands

From repository root, use the pinned environment in `requirements-lock.txt` and
the committed branch. Existing TRAIN and TEST indexes must already be complete;
this task does not construct them. TEST index filenames remain
`exp002c_s2_postings_v2.sqlite` and `exp002c_s3_postings_v2.sqlite` in a **separate
TEST index directory**. Change the example TEST directory to its actual location.

### Fixed-20k training

```bash
git switch feat/exp003-indexed-learned-reranker
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python -u scripts/train_exp003.py \
  --train-dir data/raw/train \
  --index-dir results/artifacts/exp002c_source_index \
  --results-dir results/exp003_20k
```

If only the fallback is required, use the same command with `--rule-only`
and a fresh results directory. If the main run already produced `rule14.joblib`,
use that artifact directly—do not rerun retrieval merely for reassurance.

### AWS smoke inference (four workers, 100 total S1)

Run only after reviewing training results and confirming TEST index identity.
Use a fresh shard directory for a new model/run; reuse the same path to resume:

```bash
pids=()
for shard in 0 1 2 3; do
  OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
    .venv/bin/python -u scripts/infer_exp003.py run \
    --bundle results/exp003_20k/learned.joblib --model learned \
    --test-dir data/raw/test \
    --index-dir results/artifacts/exp003_test_source_index \
    --output-dir results/exp003_test_smoke_shards \
    --shard "$shard" --smoke-limit 100 &
  pids+=("$!")
done
for pid in "${pids[@]}"; do wait "$pid" || exit 1; done
.venv/bin/python scripts/infer_exp003.py merge \
  --shard-dir results/exp003_test_smoke_shards \
  --test-dir data/raw/test --output-dir results/exp003_test_smoke_output
```

Fallback smoke: replace bundle with `results/exp003_20k/rule14.joblib`, mode
with `--model rule`, and use separate fresh shard/merge directories. This uses
its TUNE-selected threshold, not the historical EXP001 threshold by assumption.

Full TEST is **not part of this Codex run**. After smoke review and explicit
authorization, the same four-worker commands replace `--smoke-limit 100` with
`--allow-full-test`, use fresh full-run directories, and add `--allow-full-test`
to merge. Never reuse partial smoke output as a submission.

For completed full output, the official validator invocation is:

```bash
.venv/bin/python resources/validate_submission.py \
  --matching output/exp003/matching_results.tsv \
  --candidate output/exp003/candidate_pairs.tsv --test-dir data/raw/test
```

**Memory warning:** the official validator materializes candidate sets even
without `--check-ids`; hundreds of millions of candidate IDs can exceed 16 GB.
The pipeline's merge performs these structural/subset/coverage checks streaming.
On constrained AWS, validate the matching file with the official tool using
`--candidate /nonexistent/skip-candidate.tsv` (explicit warning), and retain the
streaming merge audit for candidates; use more RAM for official full-candidate
validation if required. `--check-ids` additionally loads all S2/S3 IDs. Smoke
files cannot pass full-dataset coverage validation; use a matching smoke fixture
or the merge's explicit smoke coverage check, never mistake it for full coverage.
