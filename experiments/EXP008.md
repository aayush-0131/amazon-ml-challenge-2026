# EXP008: TRAIN-only blocker recall

Status: implementation and synthetic tests complete. Full TRAIN TUNE and
EVALUATION runs are pending on AWS. No TEST input or labels are used. The new
blocker is not a leaderboard claim.

## Design and controls

EXP008 starts from the exact `32317d2d2fca72fd2bbedfb806d098173b4988d1`
EXP007 base. It reads the verified compact18 pass-eligible EXP003 pair cache as
B0. It never alters that cache or the schema-2 target indexes. A separate
country-scoped SQLite sidecar holds only new retrieval representations. The
original Unicode normalizer and the compact18 pool stay intact. The sidecar
is built only from `train_source2.tsv` and `train_source3.tsv`; its query API has
no truth or label argument. Labels in the frozen pair TSV are checked against
TRAIN truth, then the oracle predicts precisely `truth ∩ eligible`.

Variants are:

| ID | Added retrieval keys |
|---|---|
| B0 | Frozen compact18, no additions |
| B1 | AnyAscii exact transliterated name |
| B2 | EXP007 secondary core name with legal suffix removal |
| B3 | Unicode-preserving digit-letter split name and address |
| B4_12 | B1 + B2 |
| B4_13 | B1 + B3 |
| B4_23 | B2 + B3 |
| B4_123 | B1 + B2 + B3 |

Every key uses exact equality within the original country string. Keys with
more than `max_df=40` target hits are rejected, not truncated. At most 60 new
IDs per source can be added to an S1's compact18 pool. Short keys are skipped.
The default policy allows at most 1.5× the B0 average candidate count when
selecting a variant. Among allowed variants, selection maximizes exact TUNE
macro F0.5, then candidate recall, then lower candidate count and fewer passes.
All values are in `configs/exp008_blocker.json` and copied into the freeze.

The B4 names enumerate low-cost combinations so they are actual TUNE
ablations. B5 character retrieval is deferred until the TUNE miss profile
shows substantial recoverable misses; there is no unbounded fuzzy search.
This sidecar returns candidate IDs, names, addresses, source, country, and
retrieval pass. Those fields can later be fed into EXP007 feature construction
alongside compact18 candidates; matcher calibration on expanded candidates
will be a separate experiment. EXP008 does not modify EXP007.

Every `*_oracle.json` contains the exact macro F0.5, macro precision and
recall, candidate link recall, blocking FN, perfect coverage, matched entities
with no retained true candidate, mean/median/p95/p99/max candidate counts,
runtime, country slices, source slices, and source-by-country slices. The CLI
prints a compact summary. Per-variant runtime is the sum of its pass query
time and its composition/oracle time; index build and shared checkpoint I/O
are excluded. `manifest.json` also records full command wall time and
code/data/index SHA-256
identity and result hashes. `frozen_policy.json` records the selected TUNE
variant, all limits, normalization version and code hashes. Interrupted sidecar
builds resume at the last committed chunk; interrupted oracle runs resume
their per-entity SQLite hit checkpoint. Completed output directories reject
reruns. All new output lives under `results/exp008_*`, which is ignored by Git.

## AWS staging and exact run commands

Run on the existing AWS TRAIN host from its existing repository checkout.
The commands below assume the existing checkout is
`~/amazon-ml-challenge-2026` and contains the frozen TRAIN data/index/cache.
The new checkout shares those inputs read-only through paths. Run the EVALUATION
command only after inspecting the TUNE results and the frozen policy.

```bash
BASE_CHECKOUT="$HOME/amazon-ml-challenge-2026"
cd "$BASE_CHECKOUT"
git fetch origin exp/exp008-blocker-recall
git worktree add -b exp/exp008-blocker-recall "$HOME/amazon-ml-exp008-blocker-recall" origin/exp/exp008-blocker-recall
cd "$HOME/amazon-ml-exp008-blocker-recall"
mkdir -p data/raw
ln -s "$BASE_CHECKOUT/data/raw/train" data/raw/train
python -m pip install -e .
python -m pytest -q
df -h .
free -h
```

Build the two secondary indexes one at a time. Repeating a command after an
interruption resumes the `.building.sqlite` file. Completed indexes are reused.

```bash
python scripts/run_exp008.py build-index --source S2 \
  --train-dir data/raw/train --secondary-index-dir results/exp008_secondary_index
python scripts/run_exp008.py build-index --source S3 \
  --train-dir data/raw/train --secondary-index-dir results/exp008_secondary_index
```

Run all TUNE ablations and freeze the selected blocker:

```bash
python scripts/run_exp008.py tune --train-dir data/raw/train \
  --baseline-index-dir "$BASE_CHECKOUT/results/artifacts/exp002c_source_index" \
  --original-dir "$BASE_CHECKOUT/results/exp003_20k" \
  --sample-dir "$BASE_CHECKOUT/results/exp006_50k_sample" \
  --secondary-index-dir results/exp008_secondary_index \
  --output-dir results/exp008_tune
cat results/exp008_tune/frozen_policy.json
```

After verifying the TUNE results and frozen policy, run exactly one selected
EVALUATION blocker oracle. The command checks that B0 reproduces the supplied
EVALUATION macro F0.5 `0.985492979884422`, candidate link recall
`0.9596797461050202`, blocking FN `1677`, and perfect coverage
`0.8884166666666666`. A mismatch fails the gate.

```bash
python scripts/run_exp008.py evaluate --train-dir data/raw/train \
  --baseline-index-dir "$BASE_CHECKOUT/results/artifacts/exp002c_source_index" \
  --original-dir "$BASE_CHECKOUT/results/exp003_20k" \
  --sample-dir "$BASE_CHECKOUT/results/exp006_50k_sample" \
  --secondary-index-dir results/exp008_secondary_index \
  --frozen-policy results/exp008_tune/frozen_policy.json \
  --output-dir results/exp008_evaluation
```

Compare the selected EVALUATION JSON with B0. A useful result should improve
recall/oracle and reduce FN/zero-retained matched entities without exceeding
the TUNE candidate-growth guard. `results/exp008_evaluation/comparison.json`
contains the exact B0, selected, and delta values. Do not retune on EVALUATION.

## Resource planning

The sidecars duplicate target IDs, names, addresses, and up to four key rows
per target. Reserve several additional GiB per source, with temporary free
space for a `.building.sqlite` copy; check `df -h` between S2 and S3.
SQLite writes in 10k-row chunks, keeps the key index on disk, and does not
hold all 7.6M targets in RAM. One 16 GiB worker is the initial choice; the
TUNE query holds 2,001 S1 candidate sets, while EVALUATION holds 12,000 and
will need more RAM. Run sequentially and monitor RSS and disk before any
parallelization. Retrieval caps add at most 120 candidates per S1 across S2/S3.
